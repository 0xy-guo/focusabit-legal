# Focusabit 单页官网与法律页面迁移设计

日期：2026-08-26

状态：已确认设计，待实施计划

## 1. 目标

在现有 `focusabit/focusabit-legal` GitHub Pages 仓库中建设 Focusabit（微专注）官方中文网站：

- 根路径改为一页式产品官网；
- 迁移并保留现有支持与法律内容；
- 所有现有法律页面文件名保持不变，避免 App、App Store Connect 或外部链接失效；
- DNS 尚未配置时继续使用 GitHub Pages 地址预览；
- 后续配置 `focusabit.com` 时无需重新开发页面；
- App Store 尚无正式下载地址时，不提供无效链接。

本项目是面向两人团队维护的静态站点。首版只实现当前明确需要的中文官网、支持页和法律页，不增加内容管理系统、前端框架、后台接口、表单、分析工具或第三方运行时依赖。

## 2. 已确认的设计方向

整体气质沿用微专注 App 的设计系统：安静、柔和、克制、有呼吸感。页面以白色为主，少量暖灰白分区，使用低饱和品牌绿色作为强调色。

主要视觉约束：

- 页面背景以白色 `#FFFFFF` 为主；
- 品牌主色使用 `#6D927F`；
- 深色强调使用 `#475253`；
- 辅助浅绿色使用 `#B5C3BC`；
- 暖灰白分区使用接近 `#F5F3F0` 的颜色；
- 使用现有 Focusabit Logo，不重新设计 Logo；
- 保留宽阔留白、柔和阴影、低对比界面和少量立体感；
- 不使用复杂或巨大的 Logo 雕塑；
- 不使用高饱和渐变、通用科技蓝、过多卡片、夸张动画或重装饰；
- 字体使用系统字体栈，不额外下载字体。

首页核心标题固定为：

> 开启一次专注，如此简单。

首屏说明文案固定为：

> 微专注是一款安静、轻量的 iOS 专注工具。帮助你自然地进入状态，专心做好眼前的事，再慢慢找到自己的节律。

品牌辅助文案为：

> 比闹钟温柔，比任务管理简单

## 3. 技术方案

继续使用现有 GitHub Pages 静态站点，不引入 React、Vue、Astro、Next.js 或构建工具。

站点由语义化 HTML、共享 CSS、现有 Logo SVG 以及少量页面内 SVG 图形组成。首版不需要 JavaScript。锚点导航、页面跳转、响应式布局和视觉效果全部使用原生 HTML/CSS 实现。

推荐目录结构：

```text
focusabit-legal/
├── index.html                  # 新的一页式官网
├── legal.html                  # 原法律信息首页内容迁移后的入口
├── privacy.html                # 路径保持不变
├── support.html                # 路径保持不变
├── terms.html                  # 路径保持不变
├── data-deletion.html          # 路径保持不变
├── membership.html             # 路径保持不变
├── automatic-renewal.html      # 路径保持不变
├── open-source.html            # 路径保持不变
├── site.css                    # 官网样式
├── legal.css                   # 法律与支持页面样式
└── assets/
    └── focusabit-logo.svg      # 从 App 现有品牌素材复制
```

`index.html` 原有“支持与法律信息”内容迁移到 `legal.html`，避免内容丢失。原根路径将正式承担官网首页职责。

## 4. 官网页面结构

### 4.1 顶部导航

左侧展示现有 Logo、中文名“微专注”和英文名“Focusabit”。中间提供“产品”“功能”页内锚点，支持入口跳转到 `support.html`。右侧展示不可点击的“即将上线”状态。

移动端隐藏中间页内导航，保留品牌和“即将上线”状态，不增加汉堡菜单。

### 4.2 首屏

左侧依次展示：

- 小型品牌标签 `FOCUS · BREATHE · REPEAT`；
- 标题“开启一次专注，如此简单。”；
- 产品说明；
- 不可点击状态“App Store 即将上线”；
- 跳转至功能区的“了解微专注”链接；
- 品牌辅助文案。

右侧展示简洁的产品界面组合：一个主要 iPhone 界面、一个小型专注计时环和一个冥想信息提示。背景使用柔和同心光环和少量抽象小形状，不使用复杂的大型 Logo 图形。

右侧产品界面为官网展示用的 HTML/CSS 视觉组件，不伪装成可操作 App，也不使用与真实产品逻辑不一致的数据。

### 4.3 功能区

功能区使用四列，移动端改为两列或单列。四项内容为：

1. **轻松开始**：无需复杂配置，选择时间即可开始；
2. **安静专注**：克制计时界面和环境声音；
3. **片刻冥想**：五到二十五分钟的冥想指导、呼吸与放松；
4. **看见节律**：记录投入、完成与长期节奏。

“片刻冥想”使用清晰的莲花/呼吸线条图形；“看见节律”使用日历与趋势线图形。两个图形均使用页面内 SVG，避免依赖外部图片并保持高清显示。

### 4.4 产品展示区

使用整块品牌绿色背景，左侧为“为 iPhone 而设计”和产品气质文案，右侧展示三张简化的 iPhone 界面：

- 快速专注计时；
- 本周节律；
- 冥想指导。

冥想指导界面必须包含“冥想指导”标题、练习时长、引导插图、音频波形或播放状态，以及“跟随引导，慢慢呼吸”等提示，不能只显示普通计时环。

### 4.5 上线提示区

展示小尺寸 Logo、“微专注即将上线”、文案“给自己一段，不被打扰的时间。”和 `Focusabit for iPhone · 敬请期待`。

App Store 正式地址出现前，该区域不使用空链接、`#` 链接或伪下载按钮。后续只需把状态元素替换为真实 App Store 链接，不改页面结构。

### 4.6 页脚

页脚直接提供全部支持与法律页面入口：

- 隐私政策；
- 用户协议；
- 帮助与支持；
- 数据删除说明；
- 会员服务协议；
- 自动续费说明；
- 开源许可；
- 法律与支持总览。

任何一项都不隐藏在脚本菜单中。用户从官网首页最多一次点击即可到达任一具体法律页面。

## 5. 法律与支持页面迁移

现有七个具体页面的文件名和正文内容保持不变：

| 页面 | 路径 |
|---|---|
| 隐私政策 | `/privacy.html` |
| 帮助与支持 | `/support.html` |
| 用户协议 | `/terms.html` |
| 数据删除说明 | `/data-deletion.html` |
| 会员服务协议 | `/membership.html` |
| 自动续费说明 | `/automatic-renewal.html` |
| 开源许可 | `/open-source.html` |

原法律首页正文迁移至 `/legal.html`。各法律页面中原本返回 `index.html` 的“返回支持与法律信息首页”链接改为 `legal.html`。

允许调整的范围只有页面外壳：

- 顶部品牌标识；
- 导航链接；
- 返回首页或法律总览的链接；
- 共享样式与响应式布局；
- 页脚法律导航。

法律正文、日期、运营主体、联系邮箱、价格、保存期限和业务规则不在本次视觉改造中修改。若发现正文与当前产品不一致，应单独报告，不在官网改造中顺手重写。

## 6. 链接与可达性

当前线上八个地址（法律首页加七个具体页面）已检查，均返回 HTTP 200；本地现有 HTML 内部链接也全部指向存在的文件。

改造后的链接规则：

- 官网页脚直接链接全部七个具体页面和 `legal.html`；
- 法律总览直接链接全部七个具体页面；
- 每个法律页面的品牌标识返回官网根路径；
- 每个法律页面可返回 `legal.html`；
- Apple 标准 EULA、Apple 订阅管理等外部链接保持不变；
- 邮箱继续使用 `mailto:focusabit.app@icloud.com`；
- 不使用绝对 GitHub Pages 地址互相跳转，站内统一采用相对路径，以便未来无缝切换到 `focusabit.com`。

## 7. 响应式与无障碍

- 桌面端内容最大宽度约 1120px；
- 平板和窄屏将首屏改为上下排列；
- 功能区由四列降为两列，再降为单列；
- 产品界面组合在窄屏缩放并保持不溢出；
- 页脚链接允许自然换行；
- 所有页面在 320px 宽度下不得出现横向滚动；
- 使用语义化 `header`、`nav`、`main`、`section`、`footer`；
- Logo 与产品视觉提供可理解的替代文本或标记为纯装饰；
- 所有真实链接具备清晰的键盘焦点状态；
- 正文与背景保持足够对比度；
- 不依赖悬停才能看到必要信息；
- 首版不加入自动播放、滚动劫持或强制动画。

## 8. SEO 与站点元信息

首页至少包含：

- 中文页面语言 `zh-CN`；
- 标题 `微专注 Focusabit｜开启一次专注，如此简单`；
- 准确的 description；
- viewport；
- favicon / Apple Touch Icon（从现有品牌素材生成或复用）；
- Open Graph 基础标题、描述和站点名称；
- 第一阶段 canonical 指向当前可访问的 GitHub Pages 官网地址；自定义域名正式启用后改为 `https://focusabit.com/`。

法律页面保留各自独立标题和 description，不统一覆盖。

## 9. 域名与发布策略

第一阶段不添加 `CNAME`，也不在 GitHub Pages 设置中提前绑定 `focusabit.com`。原因是 DNS 尚未配置，提前绑定可能让现有 GitHub Pages 地址重定向到暂时无法访问的域名。

第一阶段发布后使用：

```text
https://focusabit.github.io/focusabit-legal/
```

进行预览和验收。

DNS 准备完成后再执行：

1. 在 GitHub Pages 设置中填写 `focusabit.com`；
2. 按 GitHub 提供的记录配置根域名 DNS；
3. 为 `www.focusabit.com` 配置指向 GitHub Pages 的 CNAME；
4. 等待证书签发并启用 HTTPS；
5. 验证根域名、`www`、全部法律页面和旧 GitHub Pages 地址的跳转行为；
6. 再把 App 和 App Store Connect 中的公开 URL 更新为正式域名。

域名配置与站点代码解耦，后续不需要重新开发页面。

### 9.1 客户端旧链接风险

当前 iOS 客户端源码中的法律页面基地址仍为：

```text
https://0xy-guo.github.io/focusabit-legal/
```

该地址及其七个具体页面目前均返回 HTTP 404。当前正常地址是：

```text
https://focusabit.github.io/focusabit-legal/
```

官网开发不修改 iOS 客户端仓库。正式发布 App 前，需要单独把客户端法律页面基地址更新为已完成 DNS 和 HTTPS 验证的 `https://focusabit.com/`，再逐个验证 App 内所有法律入口。若 App 需要在自定义域名完成前测试，可临时使用当前正常的 GitHub Pages 地址，但不得带着旧 `0xy-guo` 地址发布。

## 10. 验证标准

实施完成后必须执行以下验证：

1. 启动本地静态服务器，逐个访问官网、法律总览和七个具体页面；
2. 自动扫描全部站内 `href`，确认不存在指向缺失文件的链接；
3. 确认七个原有具体法律路径未改变；
4. 对比改造前后法律正文，确认未意外修改正文事实；
5. 搜索 `【请替换`、`.example`、`TODO` 和无效 `href="#"`；
6. 检查桌面宽度约 1440px、平板约 768px、手机约 390px 和窄屏 320px；
7. 检查键盘导航、焦点状态、颜色对比、图片替代文本和无横向溢出；
8. 确认“App Store 即将上线”不可点击，不会跳转到空地址；
9. 在发布前展示最终本地预览并取得确认；
10. 未经用户明确同意，不推送远端仓库或修改 GitHub Pages / DNS 设置。

## 11. 非目标

首版明确不包含：

- 英文版或语言切换；
- 用户登录、邮件订阅、联系表单；
- App 下载统计或第三方分析；
- CMS、数据库或后端接口；
- 博客、新闻、定价页；
- 动态深色模式；
- App Store 正式下载按钮；
- DNS、证书或 GitHub Pages 自定义域名的立即变更；
- 法律正文重写或法律意见。
